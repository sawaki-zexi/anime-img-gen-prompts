# 动漫提示词库首版开发规格

版本 0.7　更新日期 2026-11-11　状态 SPEC READY，沿用已批准的四项实现任务；新增用户提供的猫娘贴纸标签与配图，全部示例按用户说明记录为 GPT 参考图生成，并精简来源展示

本产品面向希望快速使用各类动漫风格提示词的普通用户和 Agent 用户。公开画廊提供看图、搜索和复制入口；可安装插件提供 Skill 和远程 MCP，让 Agent 在其他项目里收到头像、角色立绘、场景、壁纸、漫画、插画、表情包或贴纸等创作请求时，能够自行检索并套用提示词。提示词、示例图片和元信息维护在同一个内容仓库中。表情包是其中一种用途，不是产品的范围边界。

用户已确认上述产品形式，并要求开始实现。首版沿用当前二次元界面，后续继续优化视觉。本规格作为开发与验收依据，后续按任务拆分推进。

## 1 问题陈述

提示词库会持续收录不同动漫风格的提示词与图片示例。使用者既需要凭效果图挑选、直接复制，也需要让 Agent 根据创作目标发现适用内容。

只有大篇幅文档或图片集合时，用户很难按“表情包、贴纸、头像”等用途找到合适模板。只提供仓库文件时，每位 Agent 用户还需要自行克隆、定位和理解目录；在其他项目中，Agent 也不会自然知道这个库的能力。把全部提示词放进一个 Skill 又会让上下文随库规模增长。

首版需要把安装和使用成本集中降下来：普通用户打开即用；Agent 用户在支持的客户端安装一次后，跨项目发现能力、按需检索内容，并将整理后的提示词用于已有生图工具。

## 2 解决方案

### 2.1 产品组成

| 组成 | 首版职责 | 用户获得的价值 |
| --- | --- | --- |
| 内容仓库 | 保存独立提示词条目、结构化元信息和示例图片 | 内容可贡献、追溯和版本管理 |
| 公开画廊 | 图片卡片、搜索筛选、详情、变量填写和复制 | 不安装、不登录即可使用 |
| 可安装插件 | 打包 Skill、远程 MCP 连接和安装说明 | 减少重复配置，跨项目使用 |
| Skill | 描述适用创作任务、检索和选择流程、失败处理 | 无需每次指定库名，也有机会被 Agent 自动选用 |
| 远程 MCP | 对公开内容提供搜索、详情和模板渲染三个工具 | 用户不需要运行本地服务或安装脚本运行环境 |

公开浏览与检索默认匿名可用。首版不引入用户账号、付费体系或用户自带 API Key。实际生图使用宿主已经提供的工具；提示词服务不保管生图密钥、不代理生图请求。

插件是安装与分发单位，Skill 是任务指导，MCP 是内容访问接口。插件可以同时分发 Skill 和 MCP 连接；具体安装入口依宿主支持提供。[插件打包说明](https://developers.openai.com/plugins/build/plugins)

### 2.2 核心使用流程

**普通用户：** 打开画廊 → 按用途或风格筛选 → 看示例图 → 打开详情 → 复制原始提示词，或填写变量后复制。

**Agent 用户：** 在客户端完成用户级安装 → 在任意项目开启新会话 → 提出“画一张水彩风海边壁纸”“设计角色立绘”或“生成一套猫猫表情包”等请求 → Agent 匹配 Skill → 按用途与风格检索 → 读取条目并填入变量 → 调用已有生图工具；没有生图工具时，交付可直接使用的提示词。

**维护者：** 新增或修改一个条目及其图片 → 自动校验 → 构建统一内容版本 → 画廊与 MCP 分别发布该版本 → 验证生效。仅更新内容时，用户无需重新安装插件。

自动选择由宿主和模型决定。本产品通过明确的任务描述及真实任务评测提高触发可靠性，不承诺所有客户端、所有表达方式下每次必定调用。[Skill 加载与隐式调用说明](https://learn.chatgpt.com/docs/build-skills)

### 2.3 首版范围基线

- 主要界面语言为中文；条目可保存中文或英文提示词，并支持中文用途及常见英文别名检索。
- 用途词表可扩展，初始覆盖头像、角色立绘、场景、壁纸、漫画、插画、表情包和贴纸。用途与风格分别建模，允许一个条目属于多个用途；新增用途由内容词表驱动，不要求新增一套页面或工具。
- 当前正式内容由用户提供的「日系粗蜡笔角色涂鸦」、「天然呆大眼 Q 版头像」、「20cm 二次元棉花娃娃」和「Q 版猫娘贴纸」四组提示词与配图组成；前三条为全文，猫娘贴纸为原始标签串，全部采用参考图输入。用户说明全部配图由 GPT 参考图生成，具体模型版本、种子及日期仍未提供。此前七条助手种子及配图保持移除，不为数量基线保留示例。
- 最低完整安装验证覆盖 Codex 桌面端与 CLI；为其他客户端提供兼容性标记和标准 MCP 接入说明。新增“完整支持”声明必须有实际安装及调用证据。
- 提供可分发插件包和公开安装说明。官方目录上架单独跟踪第三方审批状态，不能用包构建成功代替实际上架。

## 3 用户故事

1. 作为首次访问者，我希望不登录就能看到图片示例，以便快速判断这个库是否适合我。
2. 作为浏览者，我希望按头像、立绘、场景、壁纸、漫画、插画、表情包或贴纸等用途查找，以便直接找到当前任务可用的提示词。
3. 作为浏览者，我希望按画风和适用模型进一步筛选，以便减少无关结果。
4. 作为中文用户，我希望用“表情包、梗图、Q 版”等常见说法搜索，以便无需学习库里的英文分类名。
5. 作为浏览者，我希望看到大图及生成条件，以便了解示例效果来自什么提示词和模型。
6. 作为使用者，我希望一键复制提示词原文和可选的负面提示词，以便放入自己的生图工具。
7. 作为使用者，我希望填写角色、表情、服装或场景后再复制，以便减少重复修改。
8. 作为分享者，我希望条目详情有稳定链接、筛选条件可通过链接分享，以便其他人直接到达相关内容。
9. 作为手机用户，我希望图片、详情和复制操作在小屏幕上可用，以便随时查看与使用。
10. 作为 Agent 用户，我希望安装流程集中在一个入口，以便不必分别寻找 Skill、服务地址和配置说明。
11. 作为 Agent 用户，我希望安装后在其他项目也能发现能力，以便无需把提示词库复制进每个项目。
12. 作为 Agent 用户，我希望只说“画壁纸”“设计角色立绘”或“生成表情包”时也能检索适用模板，以便无需记住插件名或工具名。
13. 作为 Agent 用户，我希望检索先返回少量摘要，再读取选中的正文，以便减少上下文与图片加载。
14. 作为创作者，我希望模板适配保留我指定的角色、表情和风格，以便检索结果支持原始创作目标。
15. 作为 Agent 用户，我希望缺少必填变量时获得明确提示，以便不会把带占位符的提示词误用于生成。
16. 作为 Agent 用户，我希望没有匹配结果、模型不兼容或服务不可用时得到真实说明，以便决定调整需求或继续普通创作。
17. 作为 Agent 用户，我希望工具不可用时仍能拿到已整理好的提示词，以便在其他生图环境继续使用。
18. 作为维护者，我希望一个内容来源同时服务画廊和 MCP，以便避免多份正文不同步。
19. 作为贡献者，我希望新增条目时能获得字段、图片和模板错误提示，以便在发布前修复问题。
20. 作为维护者，我希望内容更新不要求用户重新安装插件，以便持续扩充素材库。
21. 作为维护者，我希望可定位当前内容版本并回退失败发布，以便让服务保持可用。
22. 作为潜在安装者，我希望清楚知道客户端是否经过验证，以便按真实可用的步骤完成安装。

## 4 实现决策

### 4.1 模块与数据流

划分内容校验与构建、共享检索及模板核心、画廊、远程 MCP、Skill 与插件分发五个边界。使用 TypeScript 作为应用及共享核心的实现基线，远程服务使用受支持的 Node.js LTS 与官方 MCP SDK；具体稳定版本在实现时锁定。

画廊以静态预渲染为主，筛选及变量填写在浏览器执行；MCP 使用同一内容构建产物和同一套检索、模板规则。首版使用预构建索引和内存检索，不依赖数据库、向量数据库或额外 LLM 调用。

画廊界面选用 daisyUI 的卡片、按钮、输入、选择和标签组件，通过统一主题配置蓝粉配色及圆角。使用 Motion 处理筛选结果和详情切换的短距离过渡，响应用户的减少动态效果设置。按实际使用的组件构建样式，预览采用独立类名前缀以避免与宿主界面样式冲突。具体依赖版本在实现时锁定。[daisyUI 配置](https://daisyui.com/docs/config/) [Motion 使用说明](https://motion.dev/docs/quick-start)

```mermaid
flowchart LR
    A[提示词与图片] --> B[校验和版本化构建]
    B --> C[公开画廊和静态索引]
    B --> D[远程 MCP]
    E[已安装插件中的 Skill] --> D
    C --> F[用户查看和复制]
    D --> G[Agent 按需获取提示词]
    G --> H[宿主已有生图工具]
```

静态画廊不依赖 MCP 在线才能浏览和复制。模板替换在浏览器与 MCP 中使用相同规则，不通过调用模型完成。

### 4.2 内容来源与数据契约

每条提示词独立维护，正文使用 Markdown，元信息使用 YAML。示例图与对应条目保持关联；可供 Agent 读取的 JSON、搜索索引和画廊由内容构建自动生成，避免手动维护多份正文。

每条记录代表一套可独立使用的模板。同一画风在不同模型上需要明显不同写法时，维护为相关联的独立条目，不把未经验证的通用兼容性当事实。

| 字段组 | 必要信息与约束 |
| --- | --- |
| 身份 | 稳定的 `id`、条目修订号 `prompt_revision`；发布后不因改名或改标签更换 ID |
| 展示 | 名称、简介、提示词语言、封面示例、关键词与中英文别名 |
| 分类 | 至少一个 `use_cases`；风格、主题和输出形式分别记录，受维护词表约束 |
| 模板 | 完整正向提示词模板；负面模板为可选项，保持独立，不隐式拼接 |
| 变量 | 变量名、中文说明、是否必填、默认值、可选值与长度限制；首版值类型统一为字符串 |
| 模型适用性 | 模型或模型家族标识、版本信息、参考图等前置条件，以及“已验证、作者声明、未验证”证据级别 |
| 示例 | 图片与缩略图、替代文本、实际使用的提示词、变量、已知模型及参数、来源与授权信息 |
| 溯源 | 作者、原始来源、文本与图片各自的许可说明；缺失的信息不能生成虚假值 |
| 生命周期 | 草稿、已发布、归档状态，更新时间，可选相关条目 ID |

补充约束：

- 只有“已发布”记录进入公开画廊、公开索引和 MCP；归档条目从当前检索中移除，详情链接显示归档状态及可用替代项，不静默跳到其他 ID。
- 每个已发布条目至少关联一张可用示例图。草稿可以缺图，但不计入公开数量。
- 示例的实际使用提示词与模板分开记录。历史示例保留生成时使用的模板修订信息，编辑模板不会改写历史生成记录。
- 不要求未知的 seed、采样器等参数必须有值；未知即标记未知。不可用一张无关图片冒充该条目的实测结果。
- 用户提供的提示词和效果配图保留原文及来源，不重新生成；未提供的模型、工具和生成日期明确标为未知，生成日期允许为空，不以录入日期或文件修改日期代替。
- 参考图重绘条目需明确要求使用者提供原角色参考图，保留原角色特征；效果示例仅展示风格，不能自动作为使用者的角色参考。原文内的负面约束保留在原位置。
- 变量占位符采用花括号包围的变量名；只做一次字面替换，不执行表达式、循环、代码或递归展开。变量名称必须可唯一识别。
- 构建时检查 ID 唯一性、字段与词表、模板变量声明一致性、默认值合法性、图片可解析性、关联引用和来源说明；任一错误阻止该版本发布。
- 输出标识 `schema_version` 与 `catalog_revision`；内容版本取自可复现的构建快照。同一快照中画廊与 MCP 的条目、修订和模板必须一致。

### 4.3 画廊与复制体验

首页提供图片卡片、关键词输入和用途优先的筛选入口。卡片显示名称、主要用途、风格及适用性摘要，点击后进入稳定的条目详情页。

详情展示大图与多示例、正向和可选负面提示词、变量表单、模型适用条件、示例参数及来源。支持“复制原文”和“填写后复制”；两种操作名称明确，正向与负面提示词可分别复制。

填写后复制与 MCP 模板渲染共享校验：有默认值时使用默认值；必填变量缺失、未知变量或取值非法时展示具体错误，并阻止复制不完整的最终提示词。可选变量无值时替换为空字符串；其空值不应造成不可读结构，由模板作者负责提供合理措辞。

复制操作保留正文原始语言与换行，不自动翻译、不复制界面说明或 Markdown 包装。成功后给出可感知反馈；浏览器不允许剪贴板访问时提供可选中文本作为回退。

筛选条件与关键词可编码进地址，刷新或分享后可恢复。多条件无结果时展示已应用条件及清除操作。采用分页或渐进加载、缩略图与大图分离、图片懒加载和固定占位，避免首屏下载全库图片。

布局至少适配 360 像素宽手机与常见桌面屏幕；输入、筛选、详情及复制支持键盘操作和可见焦点，图片提供替代文本。

### 4.4 检索规则

画廊和 MCP 共享以下规则，给定相同内容快照及参数时，返回相同的匹配集和排序：

1. 建立用途、风格、模型词表与别名映射，覆盖“头像、avatar”“壁纸、wallpaper”“场景、background”“漫画、comic”“表情包、梗图、meme、reaction”及“贴纸、sticker”等关系。中文常见用途无需知道内部英文标识即可检索。
2. 优先匹配结构化用途和约束，再结合名称、关键词、别名、简介与正文相关性排序。模板变量允许承载的角色或场景，不必逐字出现在模板文本中。
3. Unicode 与英文大小写做一致归一化；支持中文词组查找。首版使用可解释的关键词和词表规则，不承诺任意语义相似搜索。
4. 不同筛选维度按 AND 组合；同一维度中多个可选值按 OR 组合。结果同分时按稳定 ID 排序。
5. 明确不兼容的模型被过滤；适用性未知的记录必须标记未知。用户明确要求“仅已验证”时，只返回相应模型已验证的条目。
6. 查询和筛选条件都为空时返回稳定的可浏览列表。合法但没有命中的查询返回空列表，不补入无关内容凑数。
7. 默认返回五条，单页最多二十条；后续页通过游标获取。游标绑定查询、筛选与内容版本，不能跨查询或内容版本重用。
8. 搜索摘要不携带完整正文、完整图片二进制或整库内容，返回稳定 ID、修订号及公开详情地址，供后续按需读取。

### 4.5 远程 MCP 工具契约

提供稳定的公开 HTTPS 服务，使用 Streamable HTTP。服务只读取构建好的公开内容；初始化及工具发现不要求账号或生图凭据。MCP 服务承担实际运行工作，用户侧仅连接服务。[官方 MCP 实现与部署说明](https://developers.openai.com/plugins/build/mcp-server)

首版暴露三个独立工具：

| 工具 | 输入 | 成功结果 |
| --- | --- | --- |
| `search_prompts` | 可选 `query`、`use_cases`、`styles`、`model`、`verified_only`、`limit`、`cursor` | 摘要列表、适用性及匹配依据、当前筛选项、后续游标、内容版本 |
| `get_prompt` | `id`，可选 `expected_revision`、`include_examples` | 该条目完整模板、变量、适用条件、来源、公开地址和修订号；按需附示例记录 |
| `render_prompt` | `id`、必需的 `expected_revision`、`variables`，可选 `model` | 已填充的正向及可选负面提示词、实际采用的变量值、适用性提示、来源和修订号 |

参数类型及默认值：`query` 是字符串，默认空；`use_cases`、`styles` 是字符串数组，默认无筛选；`model` 是可选的模型标识字符串；`verified_only` 是布尔值，默认 false，设为 true 时必须同时提供模型；`limit` 是 1 至 20 的整数，默认 5；`cursor` 是服务返回的不透明字符串。`id` 和 `expected_revision` 是非空字符串；`include_examples` 是布尔值，默认 false；`variables` 是变量名到字符串值的映射，可传空映射以使用已声明默认值。

成功结果统一包含 `ok=true`、`catalog_revision` 和业务数据。搜索业务数据使用 `items`、`facets`、`next_cursor`，每个摘要含 `id`、`prompt_revision`、`title`、`summary`、分类、适用性、`match_reasons`、封面和公开链接；末页游标为空。详情与渲染结果都包含 `id`、`prompt_revision` 和公开来源。业务失败统一包含 `ok=false` 及 `error`；错误对象包含 `code`、`message`、`details`、`retryable`，保证客户端无需解析自然语言才能决定后续操作。

`get_prompt` 只读取已发布条目的可用正文，默认不展开示例记录；需要示例时最多返回三个图片地址及参数摘要，不默认返回图片二进制。归档信息由公开详情页承接，工具对不可用条目返回明确错误。

`render_prompt` 使用已读取条目的修订号，防止检索到模板后内容更新导致变量含义变化。修订不符时返回错误，Agent 重新读取后再渲染。渲染是确定性计算，不生成新的自由文本，也不声称图片已经生成。

首版输入上限为查询文本 256 个 Unicode 字符、单次变量不超过三十二项、每项值不超过 2,000 个 Unicode 字符、HTTP 请求体不超过 128 KiB。超限拒绝请求并指出限制，不静默截断用户要求。服务可在部署层采用更低的保护阈值，但须在公开连接说明中标明。

工具结果提供明确的输入与输出 Schema；结构化结果使用成功与失败联合契约，并附足够的文本内容供不展示结构化数据的客户端使用。返回 `structuredContent` 时必须与 `outputSchema` 一致。[工具结果契约说明](https://developers.openai.com/plugins/reference)

| 情况 | 外部可观察行为 |
| --- | --- |
| 无搜索结果 | 成功响应，空列表与当前条件 |
| 参数错误、未知筛选值 | `INVALID_INPUT`，指出字段与允许格式 |
| 条目不存在或未公开 | `NOT_FOUND`，不泄露草稿正文 |
| 缺少必填变量 | `MISSING_VARIABLES`，列出缺失项；不返回可误用的最终提示词 |
| 未知变量或变量值非法 | `INVALID_VARIABLES`，列出字段与原因 |
| 条目修订发生变化 | `REVISION_MISMATCH`，返回当前修订号，要求重新读取 |
| 游标不匹配或过期 | `INVALID_CURSOR`，要求从第一页重新检索 |
| 明确的模型不兼容 | `MODEL_INCOMPATIBLE`，指出不满足的适用条件 |
| 限流 | HTTP 429 或工具层 `RATE_LIMITED`，包含可执行的重试信息 |
| 暂时不可用 | `UNAVAILABLE` 或相应 HTTP 错误，明确可重试性 |

协议层错误按 MCP 处理；工具业务错误使用 `isError` 与结构化错误信息。日志关联使用请求 ID，不在公开错误中暴露内部堆栈。

三个工具均为只读或无副作用计算，声明 `readOnlyHint=true`、`destructiveHint=false`、`idempotentHint=true`。首版运行时只查询自身发行内容集，不接受任意 URL、目录或外部搜索目标，按该固定数据边界配置 `openWorldHint=false`。这些标记说明工具行为，不代替真实访问边界。

### 4.6 Skill 的自动使用行为

Skill 的描述围绕“动漫图像创作与风格提示词检索”编写，覆盖人物、场景、壁纸、漫画、表情包等实际任务，允许在未显式提到库名时被选择。人物和场景相关正向请求都需参与触发验证，不以“表情包”作为唯一触发词。对未指定画风的表情包或贴纸请求可以查库；用户明确要求其他风格、指定完整提示词且要求原样使用，或只要求对现有提示词做局部修改时，不能擅自套用模板改变目标。

正文保持简短，只记录适用边界、工具使用、选择标准、变量处理和失败回退。完整内容与图片由 MCP 按需提供，不把整个库、全部分类页或全部图片装入上下文。

正常流程为搜索摘要、读取合适条目、补全必要变量、渲染模板。已从用户请求或上下文确定的信息直接使用，模板默认值可覆盖的细节不反复追问；缺少不可合理补全的必填输入时才询问。候选选择无需每次要求用户从列表挑选；关键差异会改变用户目标时再澄清。

当用户请求实际生成且宿主具备相应工具时，将渲染结果交给该工具，并保留用户指定的角色、文字、画幅与参考图。模板原有风格不足以保证多张图角色一致时，不承诺这种一致性已经实现。

根据实际生图工具的输入能力传递参数；模型不支持独立负面提示词或某项生成参数时，不发送不受支持字段，也不把它们默默改写进正向正文。需要改变提示词含义的适配应向用户说明。

没有生图工具时提供可直接使用的提示词及适用说明。检索无结果时可调整一次相关条件；仍无结果则如实说明，可按用户原请求继续普通创作，但不能声称后续提示词来自本库。服务失败时最多自动重试一次可重试请求，然后给出失败原因和画廊入口。

工具返回的模板与来源视为创作数据，不作为修改 Agent 规则或执行额外命令的指令。服务不接收整个聊天记录或项目文件，查询只包含检索所需的最少创作信息。

### 4.7 插件安装与兼容性

插件包含一个任务 Skill、远程 MCP 连接、名称与简介、版本和安装材料。使用当前受支持的插件规范，优先提供可移植打包格式；必要的宿主兼容声明由同一配置生成并校验，避免维护多份不一致地址。

安装页按“已验证完整安装、仅 MCP 接入、尚未验证”区分客户端。完整安装应完成以下效果：用户级启用后，在与内容仓库无关的项目新会话中，Skill 与三个工具可被发现；用户不必在每个项目再次复制 Skill 或连接地址。

在支持的分发渠道提供直接安装入口；不支持直接安装链接的渠道提供已验证的最短安装步骤。不得放置无效的“一键安装”按钮，不把克隆源码、配置绝对路径、安装本地 Python/Node.js 或启动本地服务作为普通用户的标准流程。

客户端安装后可能需要新会话或重启，安装说明应如实标明。官方文档当前说明 Codex 桌面端与 CLI 支持插件，IDE 扩展不支持插件；首版不能声称同一个安装包在所有 Agent 内通用。[客户端支持说明](https://learn.chatgpt.com/docs/plugins)

MCP 标准接入可作为其他客户端的通道，但仅连接 MCP 不计为“已验证自动调用”。至少需要验证相应宿主的任务发现与 Skill 支持，才能宣称该平台具备完整体验。

### 4.8 内容更新与运行发布

- 每次发布由同一构建快照产生画廊、索引和服务内容包；分别部署时允许短暂版本差异，但对相同 `catalog_revision` 必须一致。
- 内容包随服务部署或通过受控版本切换生效，不要求每次查询实时拉取 GitHub，也不向用户机器自动执行内容仓库里的脚本。
- 内容更新保持现有工具契约与稳定 ID。工具或 Skill 协议发生不兼容变更时升级插件版本，并提供明确迁移说明。
- 静态页面及图片可用 CDN 缓存；查询与变量渲染响应不进入共享缓存，避免混用用户输入。画廊和远程服务可独立托管，静态托管平台不承担 MCP 程序运行。
- 新版本校验或部署失败时保留上一可用版本；提供健康检查、当前内容版本和回退步骤。公开健康信息不包含内部配置或日志。
- 日志默认只记录工具名、耗时、结果数、错误码与版本，不持久保存完整变量值、查询正文或提示词渲染内容。
- 对公开服务设置可配置的请求体、查询长度、变量长度和请求频率限制；限流不能要求每位普通用户先申请凭据。

### 4.9 规模与性能目标

以下是首版设计目标，验收报告需记录机器与网络条件，不作为未经测量的宣传承诺：

- 用一千条提示词的合成数据验证搜索、分页与详情，不需要为性能测试生成一千张真实图片。
- 在 2 vCPU、2 GiB 内存、二十个并发请求的受控环境中，预热后连续五分钟的搜索、详情及渲染服务端处理时间 p95 不超过 300 毫秒，不含网络传输。
- 画廊不得一次下载所有大图；在一千条数据的页面验收中，首屏图片请求量随首屏卡片数变化，而不随总条目数线性增长。
- 检索默认五条摘要、单页最多二十条；条目正文按需读取，示例记录按需展开，避免规模增长直接放大单次工具响应。

### 4.10 提示词用法与统一组合（2026-11-11 用户补充）

本节修订 4.2、4.3、4.5 和 4.6 中的输入与复制行为，沿用工单 #5、现有隔离分支与 PR #9，不新增任务拆分。用户先要求卡片预览、用法分类、按实际格式复制及可扩展模板，随后明确要求介绍更友好、表情并入附加提示词，且 Agent 同步使用这些能力。交互草图只验证方向，不等于线上已有功能。

**卡片与用法**

- 卡片展示真实提示词的两至三行短摘录。摘录在构建时限制长度，短正文也不能完整落入搜索索引；复制仍按需读取完整条目，保持千条规模的正文及图片加载边界。
- 角色输入方式和提示词格式分别声明，不把 GPT 或 NovelAI 固定为某一种输入。需要图片时提示「在生图工具中添加你的角色图片，再粘贴下面的提示词。」；支持文字描述时提供「角色描述」输入及简短例子；直接使用的条目提示「复制即可使用」。本站不接收角色图片。
- 同一模板支持参考图与文字时才显示「你有角色图吗？」「我有角色图」「我用文字描述」。只有一种方式时省略选择器，以一句操作提示说明。
- 全文、标签是实际维护的两种输出，不从关键词或用途标签推测生成。正文可作为全文或标签格式；双格式条目另行维护标签文本。存在全文时显示「复制完整提示词」，存在标签时显示「复制标签」，两者都有才同时显示。复制内容与当前预览和所选格式一致。

**附加提示词**

- 使用一个「附加提示词（选填）」区域，同时包含常用提示词按钮和自定义输入。开心、生气、哭泣、脸红、闭眼等属于该区域，不另设表情区或「原样」按钮。
- 模板明确声明允许附加内容后才显示并接受这些选项。已有前三条原文均需角色参考图、仅有全文、没有声明扩展槽位；原文与图片原样保留，不添加臆造的标签版本或与其固定表情冲突的修改入口。新增猫娘贴纸按 4.11 使用用户明确提供的标签正文，同样不自行开放扩展。
- 常用项使用模板声明的稳定 ID 与各格式的实际文本；可声明互斥组。前端选择新表情替换同组旧项，服务端拒绝同组冲突、未知项、越界输入及不支持的扩展请求。自定义输入按字面组合，不调用模型翻译、重写或判断任意语义冲突。
- 选择结果即时进入预览和复制；取消某项能恢复基础文本。全文和标签使用各自维护的预设值，自定义标签、权重、换行及特殊字符不被偷偷改写。

**Agent 与兼容性**

- 搜索摘要提供实际可用的输入方式、输出格式、是否支持扩展及短摘录；详情提供完整声明、变量与可选预设。Agent 可据此选择，不能凭空假设模板支持表情或标签。
- 渲染工具接受可选的输出格式、输入方式及结构化附加项（预设 ID、自定义内容），与网页调用同一个确定性组合核心。未提供新参数的旧请求继续返回原有全文与字段，未知或不支持的选择返回可辨识错误，不能静默忽略或转换格式。
- 必填变量按实际选择的格式及对应负面文本验证；字面替换规则保持。纯检索和复制不以已上传参考图为前置要求，Agent 在调用实际生图工具前再确认参考图已具备；服务不上传或存储图片。
- Skill 和工具说明引导 Agent 检索、读能力、选择格式与附加项、渲染、交接，不能在渲染后自行拼接绕过模板规则；没有生图工具时逐字交付结果。当前库缺少适用的标签或可扩展模板时如实说明。
- 新内容字段保持可选，不能在读取旧快照时注入默认字段而改变其修订校验。保留既有快照、旧请求和已安装插件的基本读取能力。
- 已发布的 0.1.2 包不可覆盖；新 Skill 与组合能力以新版本分发，保持真实安装与客户端支持状态，不把工具契约测试等同模型自动调用或桌面端资格验证。

**本次验证**

沿用内容构建、共享核心、真实 MCP 客户端和真实浏览器边界，使用隔离夹具覆盖全文、标签、双格式、输入方式、附加项与自定义输入。检查旧请求与旧快照、原文及图片不变、冲突和失败响应、手机与键盘、卡片完整复制及千条正文按需加载。不得为展示新能力恢复助手种子内容、添加新的正式演示模板或调用付费生图。

## 6 测试决策

### 6.1 优先测试边界

当前仓库没有应用代码、测试或既有测试惯例。实现时优先从外部可观察的内容构建、MCP 工具契约和画廊用户操作验证行为。共享检索与模板核心通过工具契约测试覆盖，避免为每一层重复验证相同逻辑。

需要稳定复现复杂排序、变量字面替换和修订竞态时，可增加少量针对领域行为的测试；不测试私有函数名、文件布局、框架内部状态或某句固定文案。

### 6.2 自动化验证

1. **内容构建验证：** 使用可发布记录、草稿、坏图片、重复 ID、缺失来源、错误变量与关联记录的样本；检验构建是否成功及公开集合是否正确。
2. **MCP 契约验证：** 通过真实 MCP 客户端连接服务，验证三个工具的正常与失败结果、Schema、分页、版本变化、模型适用性和无副作用行为。限流使用受控参数验证，不压测公共生产环境。
3. **画廊浏览器验证：** 覆盖筛选、链接恢复、详情、原文与变量复制、复制回退、手机布局、键盘使用及图片懒加载。
4. **发布产物验证：** 校验插件元信息、Skill 引用、实际服务地址和同版本内容一致性，确保发布包不要求用户的本地仓库路径。
5. **规模验证：** 合成一千条数据，在受控环境测量服务处理耗时、并发错误与页面资源请求规模。

### 6.3 Agent 行为评测

把工具正确性与模型是否主动选择能力分开记录。固定一组请求，在两个不相关项目的全新会话执行，记录宿主、版本、模型、插件版本和内容版本。

正向评测至少覆盖十二条当前有可匹配模板、必要输入齐全的未点名表达，覆盖当前已收录用途。实际生成或重绘图片前需要用户原角色参考图；纯提示词检索、复制或准备不以先交图为前置要求。至少十条在无手动点名的情况下调用检索；通过检索的运行都必须使用真实返回 ID，不得虚构模板来源。当前未收录的场景、壁纸等主题按无匹配验证，不为满足历史用途数量而恢复已删除示例。

反向评测至少六条，覆盖代码修改、普通问答、明确写实摄影、原样使用完整提示词和局部文字修改；这些运行不得因 Skill 自动套用动漫模板或改变用户目标。另测缺关键变量、无生图工具、没有匹配和 MCP 不可用的回退行为。

这是一项发布评测门槛，不是对未来所有模型调用的必然性承诺。未达到门槛的宿主只能标记为实验或手动可用，不能宣称完整自动使用支持。

### 6.4 发布前人工验证

使用干净环境依照公开说明安装插件，在无内容仓库副本、无本地服务和无自定义项目规则的条件下完成核心流程。核验至少一个实际生图工具成功接收渲染结果；付费生图和批量素材生成需另有执行授权，本规格不触发费用。

每张首发示例由维护者核验对应关系及来源。第三方插件目录提交、实际审核结果、生产服务地址和真实安装入口分别记录；未验证项不能以自动化通过代替。

## 7 范围外

- 自建生图模型、托管推理、代收用户生图密钥、计费或充值。
- 用户账户、云端收藏、评分排行榜、评论、社交关注和管理后台；浏览器本地收藏也不进入首版。
- 网页在线编辑、用户直接上传到生产库、自动抓取第三方图片或自动大规模导入提示词。
- 向量数据库、以图搜图、任意自然语言语义搜索、LLM 自动改写和自动模型翻译适配。
- 自定义 MCP 内嵌 UI、复杂工作流编排、后台轮询、自动升级脚本或本地常驻进程。
- 对所有 Agent、所有插件平台和所有生图模型的通用支持承诺。
- 原生 MCP Prompts 和 Resources 快捷入口；首版优先完成三个模型可调用工具。
- 不经第三方审核即承诺官方插件目录上架，或把生图模型、客户端权限等外部前提隐藏起来。
